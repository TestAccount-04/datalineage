    1. Executive Summary & Core Stack

    Enterprises rarely operate a single technology stack. A typical estate contains Java and Python microservices, SQL databases, stored procedures, ETL orchestrators, Kafka topics, cloud warehouses, and BI dashboards.

    Rather than relying on a single tool, catalog, or nondeterministic LLM, LineageForge implements an evidence-backed lineage fabric combining static, metadata, and runtime evidence into a unified internal model.

    Capability Recommended Technology Architectural Rationale
    Code Parsing Tree-sitter + Language Adapters Multi-language concrete syntax trees; error-tolerant deterministic parsing.
    SQL Parsing SQLGlot 20+ SQL dialects supported in Python with CTE scope traversal.
    Runtime Events OpenLineage Common event standard for Spark, Airflow, and Flink execution telemetry.
    Graph Store Neo4j Property graph optimized for 8+ hop traversals and Cypher queries.
    State Store PostgreSQL ACID relational state for tenancy, connector watermarks, and audit.
    UI Canvas React Flow High-performance interactive node-edge canvas with progressive disclosure.

    3. The 3 Evidence Planes

    Every edge in the graph carries proof from one or more distinct evidence planes:

    Evidence Plane Sources Key Strengths Inherent Limitations
    Static Evidence Git repositories, Java/Python code, dbt YAML, SQL files. Works pre-execution; catches rare disaster recovery paths. Cannot prove if conditional branches actually executed.
    Metadata Evidence DB Information Schemas, DataHub, OpenMetadata, Glue. Authoritative schema structures and column definitions. Stops at catalog boundary; misses internal code math.
    Runtime Evidence OpenLineage run events, query audit logs, OpenTelemetry traces. Proves what actually executed in production. Limited to active retention windows; misses unexecuted jobs.

    5. Canonical Graph Schema (ERD)

    The internal graph model is vendor-agnostic and enforces strict separation between data flow (TRANSFORMS_TO) and control scheduling (DEPENDS_ON):

    🏛️ 1. Governance & Systems
    🏢 Organization / Domain
    Attributes: id, name, risk_tier, business_unit
    [:owns] ➔ System
    💻 System / Application
    Attributes: app_code, tier, squad_owner
    [:contains] ➔ Repository
    📁 Repository / File
    Attributes: git_url, branch, file_path, commit_sha
    [:declares] ➔ Code Symbol
    ⚙️ 2. Logic & Execution
    ⚙️ Code Symbol
    Type: Method, Function, SQL Statement, DDL
    [:READS_FROM / :WRITES_TO] ➔ Dataset
    🔄 Pipeline / Job
    Platform: Airflow DAG, dbt Model, Spark Job
    [:triggers] ➔ Execution Run
    ⏱️ Execution Run
    Run: run_id, start_time, exit_code, facet_json
    [:OBSERVED_IN_RUN] ➔ Dataset
    🗄️ 3. Data Assets & Schemas
    🗄️ Dataset (Table / Topic)
    URI: 6-tuple canonical URI, storage_engine, env
    [:contains] ➔ Field
    📋 Field / Column
    Attributes: name, data_type, nullable, pii_flag
    [:TRANSFORMS_TO] ➔ Field (CLL)
    📈 4. Product Consumers
    📊 BI Asset (Dashboard)
    Attributes: workspace, report_id, visual_tile, owner
    Dataset ➔ [:consumed_by]
    🤖 ML Asset (Feature View)
    Attributes: feature_store, model_endpoint, version
    Dataset ➔ [:feeds_features]

    6. 12 Real-World Engineering Challenges & Solutions

    The platform directly solves twelve fundamental enterprise challenges:

    Challenge Core Engineering Obstacle Platform Solution
    6.1 Polyglot Code Mixed Java, Python, Scala, and SQL. Tree-sitter AST queries with framework-specific I/O adapters.
    6.2 Complex SQL Nested CTEs, window functions, and joins. SQLGlot backward CTE scope tracing down to physical tables.
    6.3 Stored Procedures Logic hidden in Oracle PL/SQL or T-SQL. Read-only DDL catalog extraction + procedural DML analysis.
    6.4 ETL Orchestrators Airflow task order $\neq$ data flow. OpenLineage dataset facets + dbt manifest.json integration.
    6.5 APIs & Kafka Data jumps across HTTP or topic boundaries. OpenAPI specs and Kafka Schema Registry topic nodes.
    6.6 BI Semantic Layers Calculated measures hidden in dashboards. Native BI metadata APIs extracting DAX/Calculated fields.
    6.7 Dynamic SQL Runtime string-concatenated SQL queries. Tagged as Candidate/Unknown until query history proves execution.
    6.8 Identity Clashes Identical table names across environments. Canonical 6-tuple URIs (dataset://platform/tenant/env/cluster/db/schema/tbl).
    6.9 LLM Hallucinations AI models invent plausible-looking links. Deterministic-first parsing; engine operates with LLMs disabled.
    6.10 Impact Analysis Developers don't know what changes break. Forward Cypher graph traversal with bounded hop limits.
    6.11 Incremental Updates Full graph rebuilds are unscalable. Git diff parsing re-evaluates only changed files and symbol neighbors.
    6.12 Enterprise Security Code contains secrets and sensitive PII. Automated regex/entropy secret scrubbing prior to graph ingestion.

    10. Risk Management Matrix

    Risk Operational Impact Mitigation Engineering Strategy
    False-Positive Edges Users lose trust; blast alerts become noise. Mandatory inspectable proof; precision target >95%.
    Silent Coverage Gaps Partial graph gives false sense of security. Coverage Dashboard explicitly surfaces unparsed files & unknown edges.
    Dynamic SQL Runtime string queries cannot be parsed statically. Augment with query history logs; flag unverified queries as Unknown.
    Identity Collisions Dev and Prod tables erroneously merge. Strict canonical 6-tuple URIs; never fuzzy-merge production assets.
    Graph Hairball 10,000+ nodes overwhelm UI. Progressive disclosure in React Flow: subgraphs collapsed by default.

    11. Comprehensive Glossary

    Term Architectural Definition
    Data Lineage The recorded lifecycle of data: origin, transformations, and destinations.
    Upstream / Downstream The source side (provenance) vs. consumer side (blast radius) of any selected asset.
    Evidence Record Auditable physical proof backing an edge: file path, line range, commit hash, and query ID.
    Control Dependency Execution ordering (Airflow Task A >> Task B) without physical data movement.
    Canonical URI Global 6-tuple identifier preventing environment collisions.
    Blast Radius The full downstream subtree of systems affected when an upstream asset changes.
