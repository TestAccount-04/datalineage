👻 Riddle 3: The Ghost Dependency (Control vs. Data Flow)
PRECISION RULE

The Puzzle: In Apache Airflow, Task A >> Task B defines execution sequence. Does that mean data physically flows from Task A to Task B?

⏱️ Control Flow: DEPENDS_ON
Airflow Task Graph: Task A triggers Task B in temporal sequence (e.g., Slack alert, lock cleanup).
Warning: Drawing data lineage arrows here creates false ghost links!
📦 Physical Data Lineage: TRANSFORMS_TO
Byte Movement: Task A writes physical records to Postgres/S3, and Task B reads those exact bytes.
Our Rule: We never draw a data arrow unless bytes physically moved.

    3. The 3 Evidence Planes

    Every edge in the graph carries proof from one or more distinct evidence planes:

    Evidence Plane Sources Key Strengths Inherent Limitations
    Static Evidence Git repositories, Java/Python code, dbt YAML, SQL files. Works pre-execution; catches rare disaster recovery paths. Cannot prove if conditional branches actually executed.
    Metadata Evidence DB Information Schemas, DataHub, OpenMetadata, Glue. Authoritative schema structures and column definitions. Stops at catalog boundary; misses internal code math.
    Runtime Evidence OpenLineage run events, query audit logs, OpenTelemetry traces. Proves what actually executed in production. Limited to active retention windows; misses unexecuted jobs.

    6. 12 Real-World Engineering Challenges & Solutions

    The platform directly solves twelve fundamental enterprise challenges:

    Challenge Core Engineering Obstacle Platform Solution
    6.1 Polyglot Code Mixed Java, Python, Scala, and SQL. Tree-sitter AST queries with framework-specific I/O adapters.
    6.2 Complex SQL Nested CTEs, window functions, and joins. SQLGlot backward CTE scope tracing down to physical tables.
    6.3 Stored Procedures Logic hidden in Oracle PL/SQL or T-SQL. Read-only DDL catalog extraction + procedural DML analysis.
    6.4 ETL Orchestrators Airflow task order $\neq$ data flow. OpenLineage dataset facets + dbt manifest.json integration.
    6.5 APIs & Kafka Data jumps across HTTP or topic boundaries. OpenAPI specs and Kafka Schema Registry topic nodes.
    6.6 BI Semantic Layers Calculated measures hidden in dashboards. Native BI metadata APIs extracting DAX/Calculated fields.
    6.7 Dynamic SQL Runtime string-concatenated SQL queries. Tagged as Candidate/Unknown until query history proves execution.
    6.8 Identity Clashes Identical table names across environments. Canonical 6-tuple URIs (dataset://platform/tenant/env/cluster/db/schema/tbl).
    6.9 LLM Hallucinations AI models invent plausible-looking links. Deterministic-first parsing; engine operates with LLMs disabled.
    6.10 Impact Analysis Developers don't know what changes break. Forward Cypher graph traversal with bounded hop limits.
    6.11 Incremental Updates Full graph rebuilds are unscalable. Git diff parsing re-evaluates only changed files and symbol neighbors.
    6.12 Enterprise Security Code contains secrets and sensitive PII. Automated regex/entropy secret scrubbing prior to graph ingestion.

    Risk Operational Impact Mitigation Engineering Strategy
    False-Positive Edges Users lose trust; blast alerts become noise. Mandatory inspectable proof; precision target >95%.
    Silent Coverage Gaps Partial graph gives false sense of security. Coverage Dashboard explicitly surfaces unparsed files & unknown edges.
